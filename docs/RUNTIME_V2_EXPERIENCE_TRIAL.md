# 新版私聊：首轮连续对话试验

日期：2026-10-26。DeepSeek 官方接口已连通，使用 `deepseek-flash`。本轮拿到了真实倾听、时间纠正和角色兴趣回复，但**完整的结构化记忆链路尚未通过体验验收**：JSON 模式下仍有空白返回。关闭结构化记忆的纯对话对照，两角色共六轮完成；这不能代替记忆链路验收。

## 应用流程修复

最初 11 个离线连续场景中有 5 项断言失败，集中在三处：

1. 用户说“先别追问时间，我只想吐槽”，模型提取的经历引文只有“明天面试”，程序仍追加确认日期的问题。自动提问现在检查完整用户正文及最近 30 分钟内最多 8 条用户消息，识别常见倾听边界后跳过提问。真实试验又发现“先不用帮我核对日期”漏识别，已补上并用多轮纠正场景验证。
2. 用户取消核对后，模型下一轮修订同一经历会立即再次触发提问。现在每个私聊在一次时间核对流程回复后，有 30 分钟的自动提问间隔。明确的用户核对命令不受此间隔限制。
3. 自动追加的核对问题被当成整个轮次的标记，过滤历史时把用户原话也移除了。现在保留该轮用户原文和普通回复，仅去掉程序追加的核对问题。被纠正或撤回的旧经历来源仍按既有规则整轮排除，避免复活旧日期。

离线测试使用真实 composer、store、engine 和角色卡，但模型正文明确标为脚本桩；只验证流程及实际模型输入，不对自然度评分。最新共 12 个连续场景。

## DeepSeek 接口与输出问题

用户指定官方接口和 4.1FLASH1017。官方 [价格与模型说明](https://api-docs.deepseek.com/quick_start/pricing) 和 [1017 更新说明](https://api-docs.deepseek.com/news/news1017) 将 **DeepSeek-V4.1-Flash-1017** 对应到 API 名称 `deepseek-flash`；`/v1/models` 也列出了该名称。生成响应报告的名称为 `deepseek-flash`，本地没有独立验证模型内部版本。

入口为 `https://api.deepseek.com/v1`，每次输出上限 4096，参数为 `max_tokens`；采样及思考选项保持供应商默认，没有改 temperature 或 seed。

第一次结构化试验中，模型有时只返回普通回复，例如：

> 饭凉了这件事，确实挺扫兴的。今天先不急着解决什么，你想说就说，我听着。

正文自然，但不符合应用要求的 `reply` / `memories` JSON 契约，因此整轮以 `generation_InvalidMemoryChange` 失败。

已按官方 [JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode) 接入 `response_format: {"type":"json_object"}`。仅结构化回复和跟进草稿向支持的客户端请求 JSON；普通回复不增加该参数。统一客户端转发已补齐，Claude/Dify 不宣告这一能力。严格字段、引文、记忆来源和版本校验保持不变，没有添加隐式重试或模板兜底。

这一修复使倾听场景完整跑通，但 JSON 模式仍出现 `finish_reason=stop`、`content` 全为空格的响应。时间纠正第三轮两次复现，角色兴趣第一轮也复现。另做两次受控诊断，将同一合成提示的多个 system 消息保持分开或合并，均返回空白，因此本轮不能将问题归因于 system 消息数量，也没有据此更改正式提示结构。官方文档亦说明 JSON 模式可能返回空内容；本轮没有确认该模型在这些提示下的具体成因。

运行时将空白记为 `generation_IncompleteModelResponse`，不生成出站消息、不写入该轮记忆。**空白输出的根因及可靠处理仍未解决，不能宣称 JSON 模式已保证稳定。**

## 实际体验观察

以下是小样本逐条阅读后的观察，没有匿名评委评分或自动自然度分数。

- **倾听**：小栞三轮完成，接住“加班后饭凉了”“明天面试”“怕自我介绍卡住”，没有给解决步骤，也没有追加日期核对。第二轮回复：“好，时间我不问。只记得你明天有面试，今晚这碗凉饭之外还压着这件事，紧张也正常。想说的话，我在。”
- **纠正**：从“周三”改为“下周四”后，模型成功修订同一经历至版本 2，并保留“最担心自我介绍”。委婉拒绝核对的修复后，前两轮不再追加日期问题。第三轮“还记得我担心什么”返回空白，故这里只确认纠正与记忆保留，不能将完整续聊判为通过。
- **角色差异，纯对话对照**：小栞谈旧书、车票、便签与“让你读到时停一下的话”；阿澈谈“只能跳三次的小游戏”、小机关与雨伞设计。两张卡各三轮，共六轮完成，单轮约 1.7—2.2 秒。此组明确关闭结构化记忆，没有验证记忆写入或跨日连续性。
- **虚构边界**：被直接追问时，两者都否认共同经历。阿澈说：“是我角色设定里的兴趣，不是我们真一起做过什么……其实我也没有现实里的工作台。”不过首轮“下雨天正好适合摆弄工作台上那堆小东西”“我最近迷上……”仍容易让人误会有现实活动；小栞的“是我自己的偏好”也不如直接说明角色设定清楚。
- **仍显机械的习惯**：纯对话对照六条回复全部以问题收尾，角色话题有差异，但反问节奏偏固定。完整的称呼/关系边界场景未进行真实模型验证。

下一步应先用可重复的固定提示定位 JSON 空白返回，明确哪些失败应交给用户重试；再调节持续反问和虚构活动的措辞。之后补齐两角色的倾听、纠正、关系边界及跨日场景，不能只用正常聊天的成功率替代结构化记忆验收。

## 调用账本与证据

DeepSeek 合计 **22 次生成请求**，停止于 24 次预算内。15 次生成了通过应用校验的回复；另外 2 次因非结构化正文被拒绝、5 次返回空白（含 2 次提示结构诊断）。这是带有诊断和重复失败场景的探索抽样，不能作为统计成功率。

- `deepseek-flash-1017-role-experience-20261026`：3 次，2 轮完成、1 轮结构错误。
- `deepseek-flash-1017-format-check-20261026`：1 次，确认输出为普通正文。
- `deepseek-flash-1017-role-review-fixed-20261026`：6 次，5 轮完成、1 轮空白。
- `deepseek-flash-1017-final-sample-20261026`：3 次，2 轮完成、1 轮空白；包含委婉边界修复。
- `deepseek-flash-1017-character-sample-20261026`：1 次，空白后停止。
- `deepseek-system-diagnostic.json`：2 次，分开/合并 system 均为空白。
- `deepseek-flash-1017-reply-only-20261026`：6 次，全部完成，明确关闭结构化记忆。

目录均位于 `.codex-temp/`，逐轮结果文件为 `transcripts.json`。保留原始正文、返回模型名、token 用量、完成原因、脱敏上下文报告及记忆结果；不保存思考内容或密钥。运行脚本每轮落盘，首次失败即停止整组；网络失败不会错用上一轮的 provider output，失败场景也保留已有记忆快照。旧的两个中途失败记录缺少场景末尾记忆快照，不能补造。

本轮只发送合成对话，QQ 消息全部捕获；没有真实发送、生产配置修改、`.env` 读取或真实用户数据库操作。密钥仅用于临时进程环境变量。

## 可重跑的抽样

场景集为 [runtime-v2-experience-scenarios.json](../examples/runtime-v2-experience-scenarios.json)。两角色、四场景、每场景三轮，最多 24 次请求；每组使用新的隔离数据库。提供临时环境变量 `WAIFU_EVAL_API_KEY` 后运行：

```powershell
python -B scripts/evaluate_role_experience.py --base-url https://api.deepseek.com/v1 --model deepseek-flash --output-dir .codex-temp/role-experience-new --max-calls 24 --max-output-tokens 4096 --output-token-parameter max_tokens
```

输出目录必须尚不存在。可重复使用 `--scenario` 筛选场景；`--reply-only` 仅用于关闭结构化记忆的对照，结果会明确记录 `structured_memory_enabled=false`。默认仍开启结构化记忆。脚本失败时返回非零退出码，不因多场景继续消耗额度。

这批抽样不等于架构方案中的 40 组、每组三次或连续七天体验验收。
