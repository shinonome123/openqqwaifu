# 新版私聊：角色化跟进草稿

日期：2026-10-26。接在 [经历跟进候选](RUNTIME_V2_FOLLOWUPS.md) 之后。本阶段把模板之外的角色化草稿接入既有来源、人工核对和排期流程，仅作用于新版私聊。

## 使用

1. 在「经历跟进」选择未排期、属于当前角色的候选。用户已开启主动跟进授权且未暂停，当前私聊没有待处理工作时，可以点击「生成角色化草稿」。
2. 核对来源，填写操作依据并提交。后台请求一次模型，页面立即返回；点击「刷新草稿状态」查看结果。刷新保留正在编辑的正文、时间和核对依据。
3. 生成成功后点击「选用草稿并核对时间」，可修改正文，确认时间和授权，再明确安排。生成本身不创建 Inbox、Outbox、提醒或发送任务，不消耗联系发送额度。
4. 来源与操作记录显示请求管理员、角色版本、经历版本、上下文预算和来源 ID。安排记录关联所选草稿，保留原生成文本与人工确认后的文本，以便比较。

默认模板仍单独展示，不会因失败或模型关闭而伪装为生成成功。已安排的正文不被后台生成覆盖；已有任务仍按核对后的原文发送。

## 模型上下文与输出

使用角色卡中的姓名、语言、背景、表达规则，以及当前未结束经历、来源引文和同会话同角色的近期文字历史。角色与应用边界在 system 层，经历、昵称和用户原话在 user 数据层；已确认发送/捕获的历史回复保留 assistant 角色。最后的 user 层明确标注「应用草稿请求，不是 QQ 用户发言」，不会伪造用户入站事件。

虚构语气样例不会冒充共同经历。历史图片不再次下载或送模；修订、撤回记录对应的旧历史轮次继续排除。预算使用与普通回复相同的保守 UTF-8 字节估算，优先丢弃可选样例与旧历史轮次。必须保留的角色和经历证据超预算时直接失败，不截断来源。

模型只能输出以下 JSON 之一：

```json
{"decision":"draft","text":"1—500 字正文"}
```

```json
{"decision":"abstain","reason":"insufficient_evidence"}
```

放弃原因还可以是 `not_appropriate`、`already_resolved`。后者只表示模型判断，不自动修改经历状态。空正文、额外字段、重复字段、非法原因或不完整输出都视为失败；没有第二次修复调用或模板替换。模型不解释发送时间，也没有工具权限。

## 任务、失效与恢复

追加 schema 8 的 `followup_drafts` 表。每次请求持久保存请求 ID、登录身份、候选/经历版本、来源 ID、角色版本及绑定代次、数据代次、联系规则版本、会话序号水位和时间。重复 ID、内容及身份返回同一任务，不重复调用；改动内容或身份会拒绝。

- 全局草稿队列最多 32 条，每个私聊最多一个排队/生成任务；每私聊滚动 24 小时最多请求 10 次。
- 使用独立的单并发草稿工作器，不占用普通私聊工作器；调用上限 60 秒。底层提供商超时可以更早结束。
- 接收请求、领取任务、调用模型前、提交结果和选用草稿排期时均检查有效性。新消息、待处理修订/切换、联系规则变化、暂停/撤权、候选被安排/忽略/取消、来源过期或运行路径失效都会阻止旧结果继续使用。
- 暂停后再恢复、撤权后再授权也不会复活旧草稿。未选用的成功草稿超过 24 小时失效；失效时清空草稿正文，保留脱敏来源记录。已选用草稿保留作排期审计，后续发送仍服从既有规则。
- 重启后的 `generating` 任务标记 `interrupted`，不自动重复可能已计费的请求；尚未领取的 `queued` 请求可以继续，仍重新检查条件。失败/超时/放弃后需明确请求新的任务。
- 关闭服务等待正在工作的生成器，不提前关闭其数据库或客户端。关闭等待超时后仍持有资源，待工作结束再关闭。

调用前的有效性检查是本地许可边界。检查通过后已经发给模型提供商的内容无法撤回，但后续变更会阻止其结果写回和使用；不会通过失败自动补发请求。

会话删除预览计入草稿、请求及来源记录，执行删除时先清理这些派生数据。独立删除日志重放覆盖 schema 8；旧主库恢复、删除后重开会话和迟到模型结果都不能重新创建旧文本或审计行。运行库与 `.privacy.sqlite3` 仍需配套备份，不能用旧应用直接打开 schema 8。

## 接口

沿用管理员接口 `POST /api/v2/runtime/commands`，新增 `action="followup", operation="generate"`。必填字段：

```json
{
  "action": "followup",
  "operation": "generate",
  "conversation_id": "私聊QQ号",
  "candidate_id": "候选ID",
  "request_id": "本次请求唯一ID",
  "expected_version": 1,
  "expected_data_generation": 1,
  "expected_policy_version": 2,
  "authorized": true,
  "note": "已核对用户授权与经历来源"
}
```

响应中的 `draft` 是任务状态，不是发送结果。`GET /api/v2/runtime/followups` 列表附带每个候选的最新任务；候选详情附带最近 20 条 `drafts`。状态包含 `queued/generating/ready/abstained/failed/interrupted/invalidated/used`。

选用生成文本排期时，在原有 `schedule` 请求中附加 `draft_job_id`，即使人工修改了正文也保留该引用。提交时重新验证草稿与候选的关联和当前版本。同步 HTTP 与 aiohttp 均使用登录会话身份，不相信请求体中的 `actor`。

浏览器验证 5 组流程通过：显式生成与默认授权门槛；刷新保留人工编辑；排期关联原草稿和来源记录；放弃/失败提示；中英文与 390px 手机布局。没有脚本异常或外部网络请求，截图已检查，临时测试服务已关闭。日志、结果和截图位于 `.codex-temp/runtime-v2-followup-draft-*`、`.codex-temp/runtime-draft-*`。

验证使用临时数据库、模拟模型和发送器，没有真实 QQ 发送或付费模型调用，也没有读取/修改 `.env` 或真实用户数据。因此验证的是流程与隔离，角色语言质量仍需后续受控体验。
