## 打开会话记录

启动服务并以管理员登录后，在侧栏点击「会话记录」，或访问 `/#/conversations`。尚未启用 `runtime_v2` 时显示启用说明；已经启用但还没接收私聊时显示空列表。

页面提供：

- 按私聊对象查看当前绑定的人设、版本摘要，以及失败和待核对数量。预览模式明确显示“仅捕获，未发到 QQ”。
- 按轮次查看消息作者、文本/提及/图片占位、角色版本、处理状态、失败原因。最新记录在前，顺序号保留实际入站顺序；每页 30 条，可加载更早记录。
- 已确认交付的回复与未确认草稿分开展示。生成失败、未开始处理以及角色切换事件也有记录，不要求必须存在出站消息。
- 展开“上下文与预算”，查看输入估算、输出预留、省略的历史轮次、图片数量和来源标识。估算使用保守的字节计数与图片预留，不是提供商实际计费用量。
- 为当前私聊应用角色卡。操作沿会话队列生效；角色卡编辑后可再次应用同一个角色以固定新版本。已有轮次保留旧版本，不受全局激活角色影响。

列表和详情使用稳定游标分页。消息正文只在选中会话或交付详情后返回；图片不会自动加载远程地址，也不会把原始 base64 或本地文件路径返回给页面。聊天文字与昵称按纯文本显示。

## 发送核对

点击某轮的“发送详情 / 核对”，可以看到接收对象、原草稿、平台消息 ID、发送尝试与人工核对备注。平台受理不表示对方已读。发送结果不明会阻塞该会话，其他会话继续处理。

核对必须填写备注，可执行：

- **确认已交付**：仅适用于结果不明；补记本地历史，不再次发送。在预览模式中记为捕获。
- **放弃草稿**：取消此回复并释放后续队列；保留草稿和核对记录，不加入 assistant 历史。
- **重试此草稿**：复用原回复，不重新调用模型。必须勾选已了解重复发送风险并确认。真实发送模式下会产生 QQ 发送。

页面提交核对时带上看到的发送状态和尝试次数。若另一管理员已经重试，旧页面的操作会被拒绝，需要刷新后重新核对。现有 API 客户端仍可使用旧命令格式；并发操作的客户端应同样携带这两个字段。

页面按需加载、手动刷新，不会自动重复提交核对或绑定操作。

## 管理 API

同步 HTTP 和 aiohttp 两个入口均要求管理员会话：

```text
GET /api/v2/runtime/conversations?limit=30&after_id=...
GET /api/v2/runtime/conversation?conversation_id=...&limit=30&before_seq=...
GET /api/v2/runtime/delivery?outbox_id=...
POST /api/v2/runtime/commands
```

列表返回 `next_after_id`；会话详情返回 `next_before_seq`。`limit` 允许 1—100，非法参数返回 400；未知会话返回 404；未登录返回 401，非管理员返回 403。角色绑定和核对命令沿用 [第一批实现说明](RUNTIME_V2_FIRST_SLICE.md)，核对额外支持：

```json
{
  "action": "discard",
  "outbox_id": "出站记录ID",
  "note": "核对依据",
  "expected_state": "unknown",
  "expected_attempts": 1
}
```

交付详情增加 `meta`、`character_version`、`seq` 和 `reviews`，后者返回最近 100 条人工核对记录。此次查询与界面改动不新增数据库 schema；继续使用上下文构建阶段的 schema 2。

## 上下文与角色加载

新版普通私聊由 `conversation/ReplyComposer` 发起一次结构化模型请求：运行规则、角色定义和语气示例在系统层；历史保留 user/assistant 角色；昵称和真实消息在用户层。预算不足时先移除语气示例，再按完整历史轮次移除；本轮消息或必要人设超限会明确失败。

OpenAI 兼容与 Claude 适配器保留消息角色及图片分段。当前 Dify 字符串查询接口不满足这个契约，会拒绝启用新版模型流程，不静默压平成文本。模型截断、意外工具调用及请求失败会留下失败记录，不使用模板冒充模型回复。

本轮同时修复了一个上一批遗留问题：内置 `quiet-reader`、`curious-maker` 能被列出，但运行时加载遗漏了对应模板，错误回退到默认人设。现在运行时会读取指定模板；本地卡片和导入数据的既有优先级保留。原有双角色测试已能通过。
